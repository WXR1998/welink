# 飞书企业 AI 问答机器人调研

> 把 WeLink 的 AI 问答能力通过飞书企业自建应用机器人开放，供远程人员（或本机用户）在飞书里直接提问。
> 本文档为方案调研落地，重点覆盖：需求、可行性、架构、权限、接入步骤、限制、改造清单。

## 目标与结论

**目标**：在国内、不备案、不把 WeLink 后端暴露到公网的前提下，让使用者能在飞书里用自然语言查询 WeLink 的 AI 问答能力。

**结论**：可行，且优于 Telegram。飞书自建应用机器人支持**长连接（WebSocket）**接收消息，官方明确说明“开发环境中无需提供公网 IP/域名，也无需配置防火墙和白名单”。因此可以完全绕开备案，也不用给 WeLink 开公网入站；机器人进程在 NAS 上主动出站连飞书，问题在 NAS 本机调用 WeLink 现有接口，聊天数据不经过任何公网中转。

## 为什么飞书适合这个需求

- **不备案**：长连接 / 事件订阅不需要回调 URL，不要求大陆机房的公网域名，不触发 ICP 备案。
- **不出网入站**：机器人进程主动连飞书（WebSocket），无需给 WeLink 后端绑定公网端口。
- **无需审核**：自建应用只在企业内使用，不经过飞书平台审核（只有企业内部管理员审核）。
- **门槛低**：可以创建企业或加入企业；个人可创建测试企业，每个开发者最多创建 3 个测试企业、每测试企业约 100 人；测试版应用权限变更自动生效。
- **有现成的 Go 基建**：WeLink 后端是 Go，且已有飞书 App ID / App Secret 配置字段与 tenant token 缓存逻辑（`export_feishu.go`），可复用。

### 对比

| 方案 | 是否需公网入站 | 是否需备案 | 改动量 | 备注 |
|------|--------|--------|--------|------|
| 飞书自建机器人 + 长连接 | 否 | 否 | 中 | 推荐 |
| Telegram bot（Long Polling） | 否 | 是（海外） | 中 | 国内不可用 / 需翻墙 |
| 钉钉机器人（Stream） | 否 | 否 | 高 | 需企业管理员，门槛高于飞书 |
| 组网（Tailscale / ZeroTier）+ 现有 Web UI | 否 | 否 | 低 | 适合小团队直接远程用 Web UI |
| Cloudflare Tunnel / ngrok + 公网 | 是 | 否 | 高 | 风险大，需额外鉴权与脱敏 |

## 架构

```
飞书用户发消息
        │
        ▼
飞书开放平台（事件）
        │
        ▼  WebSocket 长连接（主动出站）
NAS 上的飞书机器人网关进程
        │
        ▼  本机调用 WeLink
POST /api/ai/rag            （单联系人 / 群混合检索问答）
POST /api/ai/memory-search  （跨联系人记忆优先问答）
        │
        ▼  把 SSE delta 汇总成完整文本
飞书「发送消息」API 异步回传
```

- 常用入口：`/api/ai/rag`（`key` + `messages` + `profile_id`）与 `/api/ai/memory-search` + `/api/ai/analyze`（跨联系人记忆优先问答），这两条链路是现有前端 `LLMAnalysisTab` 与 `CrossContactQA` 在用的，机器人直接复用，不改前端。
- 网关进程在 NAS 上回环访问 WeLink 时，属于 `loopback`，现有 `pairing.go` 的 `isLoopbackRequest` 会放行；如果网关跑在 Docker 容器里（非宿主），则需显式带 `Authorization: Bearer <MobilePairingToken>`。

## 飞书开放能力要点

- **机器人能力**：在开发者后台「应用能力 > 添加应用能力」中开启「机器人」。
- **长连接（WebSocket）**：用官方 SDK 建立 WS 全双工通道，订阅 `im.message.receive_v1`。无需回调 URL。
- **3 秒约束**：事件需在 3 秒内处理完成，否则触发超时重推。所以收到消息后应先异步返回，再在后台执行 RAG + LLM，最后用发送消息 API 回传。
- **连接数**：每个应用最多 50 个 WebSocket 连接；集群模式下只有随机一个客户端会收到消息。单实例即可。
- **消息幂等**：群机器人收到的是群内广播事件；单聊是点对点消息。都需要用 `message_id` / 事务去重，避免重推导致重复回复。

## 需要申请的权限（最小集）

| 权限 | 用途 |
|------|------|
| `im:message.p2p_msg:readonly` | 读取单聊（点对点）消息 |
| `im:message:send_as_bot` | 以应用（机器人）身份发送消息 |
| `im:message.group_at_msg:readonly` | 群聊中 @ 机器人时接收消息 |

发送消息用 `tenant_access_token`，接收方建议用 `receive_id`（`chat_id` / `open_id`）。

## 接入步骤

1. 注册/创建飞书企业，进入 **飞书开放平台** 开发者后台。
2. 创建**企业自建应用**，开启「机器人」能力。
3. 按上表申请权限，并在「应用发布」中将应用**可用范围**设为指定成员（建议同时配合代码内白名单）。
4. 在事件订阅中选择**长连接**方式，订阅 `im.message.receive_v1`。
5. 获取应用的 `App ID` / `App Secret`，配置到 WeLink 或机器人网关的环境变量 / `preferences.json`。
6. 新增 Go 网关：使用 `github.com/larksuite/oapi-sdk-go/v3`，用 `larkws.NewClient` + `OnP2MessageReceiveV1` 收消息，`im/v1` 的 `message.Create` 发消息。
7. 收到消息后异步处理，调 WeLink `/api/ai/rag`（或 `/api/ai/memory-search`），把 SSE delta 汇总为完整文本，再回传。

## 会话 / 权限 / 去重设计

- **会话隔离**：单聊用 `chat_id`（或 `open_id`）映射 `conversation_key`（如 `feishu:<open_id>`）；群聊用 `chat_id + sender_id` 区分提问人，避免多人共享上下文。
- **访问控制**：应用「可用范围」限定成员 + 网关代码内白名单（Telegram/飞书 user_id 白名单）双保险；只对可信成员开放全部检索能力。
- **消息去重**：通过 `message_id` / `client_msg_id` 幂等，避免 3 秒超时重推或同一条消息被多次执行。
- **超长回答**：飞书文本消息体上限约 150KB，单条有长度限制；按段落拆分多条 `message.Create`，或只回摘要再提示“完整内容请到 Web UI”。
- **隐私脱敏**：可在网关层对来源联系人名、原文片段做脱敏（如替换 `***`），避免把敏感聊天原文直接暴露给非可信成员。

## 限制与费用

- **费用**：飞书机器人消息 API 与长连接属于基础开放能力，本身不额外收费；个人创建企业 / 测试企业即可开发。
- **容量约束**：飞书免费版有成员人数上限，成员数与高级功能由飞书版本决定；仅给少数可信成员使用通常足够。
- **使用者需在同一企业内**：使用人员要安装飞书客户端并加入你创建的企业，比 Telegram 多一步“都在同一个企业下”。
- **QPS 限制**：发送消息 API 单用户/单群约 5 QPS，整体约 1000 次/分钟。对 AI 问答（低频、慢）完全够用。
- **实时性与可用性**：依赖飞书云服务与 NAS 出网；NAS 断电 / 断网时机器人不可用。

## 改造清单

| 事项 | 现有 WeLink | 需要新增 |
|------|------------|----------|
| 飞书 App ID / Secret 配置 | 已有字段 + token 缓存 | 可复用 |
| 飞书消息收发 | 无 | 网关：SDK WS 接收 + 发送 API |
| AI 问答接口 | `/api/ai/rag`、`/api/ai/memory-search` | 复用，包一层 SSE→文本 |
| 异步返回（3s 约束） | 前端是同步连接 | 网关需异步回消息 |
| 用户白名单 / 可用范围 | 无 | 新增配置 |
