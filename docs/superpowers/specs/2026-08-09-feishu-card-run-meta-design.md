# 飞书卡片运行元信息表格化设计

## 目标

将 AI 回答完成卡片顶部的运行元信息从单行引用文本改为结构化的 Markdown 表格，同时保持其作为小字辅助信息展示在最终回答前。

## 渲染结构

`contextMetaLine` 保持现有的“上下文始于...代码...”首行。`formatAnswerRunMeta` 在其后生成三个引用区：

1. `> **模型**`
   - 一个两列表格，固定按问题分解、查询扩展、最终回答三行输出。
   - 任一模型名缺失时，该单元格显示 `-`，以维持三行结构。
   - 模型名使用行内代码。
2. `> **问题分解**`
   - 仅在存在至少一个实体、概念或时间范围时显示。
   - 两列表格逐行展示“实体”、“概念”和“时间”；只输出实际存在的维度。
3. `> **查询扩展**`
   - 仅在存在扩展查询时显示。
   - 两列表格按“序号 / 查询”逐条输出，每个查询占一行。

各表格与对应标题之间不插入空白引用行，标题、表格和已有上下文元信息之间用普通空行分隔。

## 边界与安全

- 所有来自模型的单元格文本先转义 Markdown 表格保留字符 `|` 与换行，防止一条查询破坏表格结构。
- 空条目不产生空白行。
- 不改变进度中的实时状态区；本次仅改变回答完成后的运行元信息。

## 测试

- 更新 `TestFormatAnswerRunMeta`，验证三个加粗标题、模型固定三行、问题分解表格行和逐条扩展查询行。
- 增加含 `|` 与换行的扩展查询用例，验证输出仍保持单行表格单元格。
